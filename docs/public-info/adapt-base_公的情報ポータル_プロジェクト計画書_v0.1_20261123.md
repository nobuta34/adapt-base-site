## 1. 企画概要

### 1.1 目的

国、省庁、都道府県、市区町村、公的支援機関、商工会議所などの一次情報を横断的に把握し、中小企業・個人事業主に役立つ補助金、助成金、研修、DX・IT、制度改正、経営支援の情報を検索しやすく提供する。adapt-base自身の情報収集と技術実証にも活用する。

### 1.2 解決する課題

- 情報が発行主体や地域ごとに分散し、同じテーマを継続確認しにくい。
- 複数情報源で同一制度が紹介され、重複や古い情報の見極めが難しい。
- 募集開始日・締切・更新日・地域要件が異なり、読者が必要な情報を探しにくい。
- 取得方法と再利用条件が情報源ごとに異なり、無差別な収集・再配布は運用リスクになる。

### 1.3 目標と価値

公開ページを閲覧するだけで「地域・情報分野・募集状態」で必要な一次情報に到達できることを第一目標とする。情報の完全性、助成金の交付可能性、応募適格性、申請期限の正確性を保証しない。公式サイトを最終確認先とする。

## 2. 推奨方針と設計原則

1. **既存資産優先**：既存 `nobuta34/adapt-base-site` の Hugo／Cloudflare Pagesを維持し、ポータル画面を追加する。既存サイトの大規模移行は行わない。
2. **収集と公開を分離**：取得元アダプター、正規化、保存、公開API、フロントを疎結合にする。収集器の変更が公開サイトを止めない構成とする。
3. **一次情報優先**：記事へのリンク、発信元、公開・更新・最終確認日時、期限の出典を表示する。AI生成情報は事実と区別する。
4. **利用条件ファースト**：API・RSS・HTML・メールで「収集できる」ことと「公開・配信してよい」ことを混同しない。利用条件が未確認の情報源は公開連携を保留する。
5. **無料枠中心、移行可能**：Cloudflare Workers/Cron/D1を第一候補とし、負荷増に応じて処理の分割・移転を可能とする。
6. **KISSとベンダーロック抑制**：収集ルールを設定データとして管理し、データをCSV/JSONでエクスポート可能にする。メール、AI、PDF解析は必要が生じてから追加する。
7. **GitHub正本・Drive配布**：Markdown、設定、SQL、変更履歴はGitHub PRでレビューし、Word版はGoogle Driveで参照・配布する。シークレットや非公開のメール本文はPublicリポジトリに置かない。

## 3. 対象範囲

### 3.1 初期対象

| 項目 | Phase 1の対象 | 将来拡張 |
|---|---|---|
| 地域 | 全国共通／東京都／神奈川県／千葉県／埼玉県 | 全国都道府県・市区町村 |
| 発行主体 | 国・省庁・自治体・中小企業支援機関 | 商工会議所、経済団体、業界団体 |
| 情報分野 | 補助金・助成金、創業、経営、セミナー、DX/IT、セキュリティ、制度改正 | 調達・入札、公募、事業承継、海外展開 |
| 情報源数 | 許諾確認済みの20〜30情報源を目標（仮置き） | 段階的追加 |
| 収集方式 | 公式API、利用条件適合のRSS/Atom | HTML監視、登録メルマガ、PDF抽出 |
| 公開機能 | 一覧、キーワード・地域・分類検索、詳細、一次情報リンク | パーソナライズ、通知、全文検索 |
| AI | 必須としない | 要約、関連度、更新差分評価 |

### 3.2 初期の対象外

個人情報を含む利用者会員管理、申請代行、補助金受給可否の自動判定、全文転載、無許諾のメール再配信、PDF全文のミラー配布、自治体サイトへの高頻度クロール、全自治体の即時網羅、24時間有人監視。

## 4. 初期情報源候補と確認手順

| 区分 | 情報源候補 | 入口 | 公開利用の扱い |
|---|---|---|---|
| 全国 | Jグランツ（デジタル庁） | 公式API | API仕様・利用条件・レート制限を個別確認 |
| 全国 | 経済産業省／中小企業庁 | RSS・公式一覧 | RSS/本文の利用条件を確認 |
| 全国 | 厚生労働省 | RSS・公式一覧 | 情報分野・転載条件を確認 |
| 全国 | 中小機構／IPA | 公式一覧／API等 | 各提供条件を個別確認 |
| 地域 | 関東経済産業局 | RSS・公式一覧 | 取得対象と再利用条件を確認 |
| 地域 | 東京都・神奈川県・千葉県・埼玉県 | RSS・公式一覧 | 自治体ごとに利用条件を記録 |
| 地域 | 東京都中小企業振興公社 | ニュース・支援制度一覧 | 登録メルマガの再利用可否を確認 |
| 市区町村 | 東京23区・近隣市 | お知らせ・支援制度 | 優先順位・条件確認後に追加 |

**重要**：東京都のRSS利用案内では、RSSを利用した再配布・メルマガ作成・サイト構築に事前申請を求めている。情報源ごとの許諾・申請要否を確認するまで公開取得対象に登録しない。

情報源登録時には、運営主体、カテゴリ、公式URL、RSS/APIの仕様、robots・利用規約URL、許容する保存・要約・公開・配信、確認日、責任者、再確認予定日を必須管理項目とする。

## 5. 推進体制・責任分界

| 役割 | 担当（暫定） | 責任 |
|---|---|---|
| サービスオーナー | adapt-base | 対象分野、公開判断、運用費承認、法令・規約判断 |
| 設計・実装 | adapt-base／Codex支援 | ソース調査、PoC、実装、テスト、文書化 |
| 品質・運用 | adapt-base | 監視、障害一次切り分け、データ訂正、更新停止判断 |
| AI | 補助ツール | 文案・分類候補・レビュー補助。公開・法的判断は行わない |

小規模運用のため役割は兼務可能。ただし「自動処理の判断」と「公開を許可する判断」は論理的に分離する。

| フェーズ | 期間の目安 | 主要作業 | 完了ゲート |

## 7. 要件・受入条件（暫定）

| ID | 要件 | MVP受入条件（仮置き） |
|---|---|---|
| FR-01 | 公式情報の自動取得 | 許可済みAPI/RSSを定期取得、履歴と最終成功日時を残す |
| FR-02 | 重複排除 | 同一情報源の同一ID/正規URLは1論理記事に統合、再実行で件数増加なし |
| FR-03 | 分類と地域 | 全国・都県と主要カテゴリで絞り込み可能 |
| FR-04 | 一次情報追跡 | 各公開記事に発信元、公式URL、公開/更新/確認日、出典を表示 |
| FR-05 | 公開制御 | 許諾未確認・停止・不明な情報は公開APIに出ない |
| FR-06 | 収集監視 | 失敗・無更新・構造変更を区別し管理画面またはレポートで確認できる |
| NFR-01 | 堅牢性 | 1情報源の異常で他の情報源の処理が停止しない |
| NFR-02 | 費用 | PoCでは原則無料枠内、上限超過見込みを検出できる |
| NFR-03 | 安全性 | 外部HTML・XMLを信用せず、危険な埋込みや外部参照を公開しない |
| NFR-04 | 保守性 | 新規RSS/API情報源をアダプター改修なし、設定変更中心で追加可能 |
| NFR-05 | 可逆性 | D1の主要データをCSV/JSONで取り出せる |

参考指標：許諾済み対象の収集成功率95%以上（外部障害を別管理）、更新検知遅延24時間以内をMVPの初期目標とする。これはSLAではなく、PoC結果で見直す測定仮説。

## 8. 概算コストと増加条件

| 費用要素 | 初期方針 | 増加トリガー・対応 |
|---|---|---|
| Cloudflare Pages/Hugo | 既存を継続 | 配信量・デプロイ制限の変化を確認 |
| Workers/Cron | Freeの範囲で少量分散実行 | CPU/サブリクエスト上限で小分けまたはPaidを検討 |
| D1 | Free枠を第一候補 | 読み書き回数・保存量増加で再設計 |
| AI API | Phase 1では使わない | 呼出数・トークン・モデル単価を実測 |
| メール配信 | MVPでは行わない | 同意・配信停止・配信業者費用を設計 |
| 人的工数 | 自社PoC | 情報源の利用条件確認・例外解析が最大の運用コスト候補 |

無料で運用できることは保証しない。Cloudflare各サービスの利用上限・価格は契約プランと時点により改定されるため、開始前に公式料金表で再確認する。

## 9. 主要リスクと対応

| リスク | 影響 | 初期対策 | 残課題 |
|---|---|---|---|
| 公開/再配布禁止 | 高 | source単位で公開既定OFF、利用条件証跡 | 自治体ごとの申請・個別判断 |
| 元情報の変更・消失 | 高 | 原文URL、確認日時、差分メタデータ | 訂正・削除と追随処理 |
| 情報の期限誤認 | 高 | 日付型・タイムゾーン・出典を分離 | PDFのみの期限や延長公告 |
| ソース構造変更 | 中 | アダプター別テスト、異常件数検知 | 手動保守コスト |
| 無料枠超過 | 中 | バッチ制限、上限監視、キルスイッチ | 有料移行条件 |
| 重複・誤分類 | 中 | ID/URL優先、手動訂正 | 横断名寄せ精度 |
| 情報源の障害 | 中 | 条件付きリクエスト、バックオフ、隔離 | 停止情報の表示方針 |
| AIの幻覚 | 中 | AIは補助、原資料優先 | 自動公開の可否 |
| Publicリポジトリへの機密混入 | 高 | シークレットの外部保管、PRチェック | 実環境アクセス監査 |

## 10. 管理・運用と品質レビュー

- **日次**：成功/失敗件数、最終成功、追加件数0の妥当性、期限切れ、公開保留を確認。
- **週次**：未解決エラー、20件程度の標本による分類・公式リンク検証、CPU/DB利用量。
- **月次**：情報源の利用条件見直し、価値の低い情報源停止、ドキュメント更新、データ削除・保持点検。
- **変更時**：PRレビュー、スキーママイグレーション、バックアップ/ロールバック計画、公開API互換性確認。
